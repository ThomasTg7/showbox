# Plan 05 — Rankings y títulos · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rankings versionados (pro y amateur; P4P y por división) ordenados a mano con sugerencias tras cada evento, campeón actual por división y nivel, y su visualización pública con movimiento ▲▼.

**Architecture:** Lógica pura en `src/domain/rankings.ts` (movimiento entre versiones, sugerencias, reglas). Cada guardado crea una nueva versión inmutable (`ranking_versions` + `ranking_entries`); la pública es la última versión del alcance. Títulos en `titles` (uno por división y nivel).

**Tech Stack:** Heredado. dnd-kit para ordenar.

**Spec:** `docs/superpowers/specs/2026-09-28-guerra-campal-design.md` (§4.7)

## Review Focus

- Primera versión de un ranking: todos los puestos se muestran como NUEVO (no hay versión anterior).
- Peleador que pasa a retirado estando rankeado: el panel muestra aviso "Pérez está retirado: quítalo del ranking" y la vista pública no lo muestra.
- Coronar campeón a alguien que está #2 en su división lo quita del ranking numerado al guardar la nueva versión.
- Guardar un ranking con más entradas que `ranking_slots` debe rechazarse.
- Sugerencias no se repiten si el admin ya las descartó para ese evento.

### Task 1: Dominio de rankings

**Files:**
- Create: `src/domain/rankings.ts`, `src/domain/rankings.test.ts`

**Interfaces:**
- Produces:
  ```ts
  type Movement = { kind: 'up'|'down'; by: number } | { kind: 'new' } | { kind: 'same' };
  computeMovement(current: string[], previous: string[] | null): Map<string, Movement>  // arrays de fighterId por posición
  type RankingSuggestion =
    | { kind: 'move'; fighterId: string; toPosition: number; reason: string }
    | { kind: 'enter'; fighterId: string; toPosition: number; reason: string };
  suggestAfterEvent(input: {
    ranking: string[]; championId: string | null; slots: number;
    results: { winnerId: string; loserId: string; winnerName: string; loserName: string }[];
  }): RankingSuggestion[]
  validateRanking(entries: string[], ctx: { slots: number; championId: string|null; eligible: Set<string> }): string[] // errores
  ```
  Regla de sugerencia: si el ganador está peor rankeado (o sin ranking) que el perdedor rankeado, sugerir moverlo/entrarlo a la posición del perdedor; `reason` = `"Soto (#4) venció a Herrera (#2)"` o `"Lagos (sin ranking) venció a Muñoz (#3)"`. Vencer al campeón no genera sugerencia de ranking (lo maneja el cambio de título).

- [ ] **Step 1: Tests que fallan:** `computeMovement(['a','b','c'], ['b','a','d'])` → a `up 1`, b `down 1`, c `new`; `previous null` → todos `new`; `suggestAfterEvent` casos de `move` y `enter` con los textos exactos; ganador mejor rankeado que perdedor → sin sugerencia; `validateRanking` con campeón dentro → `'El campeón no puede estar en el ranking numerado'`, con 6 entradas y 5 puestos → `'Máximo 5 puestos'`, duplicado → `'Peleador repetido'`, no elegible → `'<id> no es elegible'`.
- [ ] **Step 2:** FAIL → implementar → PASS.
- [ ] **Step 3: Commit** `feat(domain): ranking movement, suggestions and validation`
